# AI 驱动的 A 股量化投资辅助系统产品需求文档

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | QuantAgent v2（暂定） |
| 目标市场 | 中国 A 股 |
| 初始模拟本金 | 100,000 元 |
| 产品阶段 | 研究、投资辅助、回测与模拟交易 |
| 核心技术 | 确定性量化策略 + LLM 研究辅助 + 遗传算法优化 |
| 文档状态 | 初始需求基线 |

## 2. 产品愿景

建设一个面向个人 A 股投资者的量化投资辅助系统，能够持续完成市场监控、
财务分析、盘中行情监控、个股筛选、仓位管理、风险控制、交易计划生成和盘后
复盘。

系统以 100,000 元模拟本金为起点，采用波段趋势和尾盘超短两类策略，在严格
控制风险和执行纪律的前提下，对资金进行分舱管理。系统通过 LLM 提升研究和
复盘效率，通过遗传算法搜索策略参数，但所有策略进化必须经过可重复回测、
样本外验证和模拟盘考验，并保留完整、可追溯的实验记录。

产品不承诺收益，不把预测结果视为确定事实。第一阶段只提供投资辅助和模拟
交易，不自动连接真实资金。

## 3. 核心目标

### 3.1 投资研究

- 自动监控大盘、行业、概念和个股状态。
- 获取并分析上市公司财务数据、公告和重要新闻。
- 识别市场风险、行业景气变化和个股异常。
- 为每个候选标的生成结构化分析、交易计划和失效条件。

### 3.2 策略执行

- 建立一套以趋势和基本面质量为基础的波段策略。
- 建立一套以胜率和纪律为优先的尾盘超短策略。
- 分别管理两类策略的资金、持仓和绩效。
- 将策略观点、订单意图、风控结果、模拟成交和持仓严格分离。

### 3.3 资金和风险管理

- 以 100,000 元建立完整模拟账户。
- 控制单票、单策略、单行业和账户总体风险。
- 建立止损、止盈、移动止损、时间止损和回撤熔断规则。
- 在连续亏损、行情异常或系统故障时自动降低风险或停止交易。

### 3.4 自动进化

- LLM 负责提出研究假设、分析实验和解释结果。
- 遗传算法负责在明确范围内搜索策略参数。
- 每次实验保存数据、代码、参数、结果和晋升原因。
- 策略只能逐级从研究候选晋升至模拟盘候选。
- 实盘部署必须经过独立审批，不能由 LLM 或 GA 自动完成。

## 4. 产品边界

### 4.1 第一阶段包含

- 历史行情和财务数据管理。
- 实时或准实时市场监控。
- 波段和尾盘超短策略。
- A 股规则约束下的可信回测。
- 100,000 元模拟账户。
- LLM 研究、解释和复盘。
- GA 参数实验和进化谱系。
- 投资建议、风险提示和 Dashboard。
- 人工确认后的手动下单辅助。

### 4.2 第一阶段不包含

- 自动向券商提交真实订单。
- 融资融券、期权、期货和高频交易。
- LLM 自主决定真实下单金额。
- GA 自动替换生产策略。
- 保证固定收益或持续盈利。
- 绕过交易所、券商或监管要求的交易方式。

## 5. 用户工作流

### 5.1 盘前

1. 更新历史行情、财务数据、公告和新闻。
2. 分析大盘趋势、市场情绪、行业强弱和风险状态。
3. 检查现有持仓风险、止损线和预期事件。
4. 输出盘前简报和当日风险预算。

### 5.2 盘中

1. 监控大盘、行业和持仓价格变化。
2. 监控成交量、波动率、涨跌停和异常行情。
3. 对触发风险规则的持仓生成告警。
4. 记录信号、告警和用户决策，不自动绕过人工确认。

### 5.3 尾盘

1. 在指定时间窗口扫描全市场。
2. 运行尾盘超短策略。
3. 过滤 ST、退市、停牌、流动性不足和数据异常证券。
4. 计算候选标的评分、次日计划、止损和仓位上限。
5. 输出排序后的候选清单，由用户确认是否执行。

### 5.4 盘后

1. 对账模拟订单、成交、现金和持仓。
2. 计算每个策略资金舱的独立绩效。
3. 分析计划与实际执行之间的偏差。
4. 记录失败交易、纪律违反和数据异常。
5. 由 LLM 生成结构化复盘和待验证假设。

## 6. 策略资金舱

### 6.1 波段趋势舱

#### 目标

选择趋势结构良好、基本面质量可接受、相对市场更强的个股，持有数个至数十个
交易日，追求合理盈亏比和可控回撤。

#### 候选因子

- 日线和周线趋势。
- 均线方向及排列。
- 放量突破和成交活跃度。
- 相对大盘、行业和同类个股的强度。
- 营业收入、利润、现金流和资产负债质量。
- 估值与行业位置。
- 行业景气和市场状态。
- 公告、新闻和潜在事件风险。

#### 退出规则

- 初始止损。
- 移动止损。
- 趋势结构破坏。
- 达到预定目标后分批退出。
- 持有时间超限但走势未兑现。
- 大盘或行业风险状态显著恶化。

### 6.2 尾盘超短舱

#### 目标

在尾盘选择当日走势和资金行为得到确认的强势个股，计划于下一交易日根据
冲高、开盘强弱和风险规则退出。该策略以胜率、纪律和回撤控制为最高优先级。

#### 候选因子

- 尾盘价格位置和量价结构。
- 当日涨幅和振幅。
- 成交量、换手率和流动性。
- 板块强度和板块内联动。
- 相对大盘强度。
- 尾盘资金行为。
- 次日可能面临的公告和事件风险。

#### 次日退出状态机

- 高开并快速冲高。
- 平开后走强。
- 高开低走。
- 低开后修复。
- 低开继续走弱。
- 涨停、跌停、停牌或无法成交。

每种状态必须有确定性的观察时间、止盈、止损和退出规则，不能由 LLM 临场
自由发挥。

#### 第三交易日延长持有

定义买入日为 `T0`，次一交易日为 `T1`，第三个交易日为 `T2`。尾盘超短仓位
默认在 `T1` 退出；只有在 `T1` 的固定决策时点重新评估并通过全部门禁时，
才允许延长持有至 `T2`。延长持有不能由 LLM 临场主观决定。

“`T2` 继续上涨”的监督学习目标必须基于可成交价格和净收益定义：

- 初始实验将 `T1 14:45` 设为固定决策时点，以该时点可成交卖出价格作为
  “立即退出”基准。
- 初始实验使用 `T2 09:35～10:30` 的保守可成交均价作为延期退出价格，
  不使用当日最高价。
- 扣除买卖佣金、印花税、过户费和保守滑点后，净收益达到实验配置中的
  最低目标，标签才记为成功。
- 涨停无法成交、停牌、流动性不足或数据缺失不能记为普通成功样本。
- 最低净收益目标、退出窗口和滑点必须版本化，并通过训练集之外的数据选择，
  不得为了提高胜率回看结果后修改。

延长持有至少同时满足：

- **强逻辑**：存在可验证、带来源和时间的业绩、公告、行业景气、政策或供需
  催化；LLM 只负责抽取和归类，不能凭叙事直接决定持有。
- **板块联动**：所属板块相对市场保持强势，板块上涨家数、成交额或多只核心
  个股共同确认，不能仅由单只股票拉升构成。
- **个股确认**：相对强度、收盘位置、量价结构、流动性和趋势未出现确定性
  破坏，且不是无法正常成交的一字涨停。
- **市场环境**：主要指数、市场广度和短线风险状态没有触发降仓或熔断。
- **次日持续性**：`T1` 的价格和成交行为继续验证 `T0` 假设；冲高回落、
  放量滞涨、板块退潮或跌破失效位时禁止延期。
- **事件安全**：`T2` 前没有已知的财报、减持、解禁、监管、停复牌等未被
  风险预算覆盖的事件。
- **风险收益**：扣除完整成本后的条件期望为正，预设止损、最晚退出时间和
  最大仓位均通过统一风险门。
- **概率可信**：冻结模型在严格样本外数据上输出校准概率不低于 0.80；
  同一概率分桶必须有足够样本，并同时报告实际成功率、Brier Score、可靠性
  曲线和置信区间。

初始成功标签定义为：与 `T1 14:45` 立即退出相比，延期至 `T2` 退出窗口后的
净资产增量不低于 `0.5%`，且期间未触发预设止损或不可成交风险。`0.5%` 是
待验证的研究基线，不是收益承诺；后续只能通过版本化样本外实验调整。

80% 高置信门禁初始还要求：独立样本外的 `P >= 0.80` 概率桶至少积累 100 个
有效样本，实际成功率不低于 75%，且校准误差和置信区间达到实验规范。未达到
最小样本数时，即使单次模型输出超过 0.80，也不得延期持有。

在样本量、概率校准或任何必要条件不满足时，系统必须按默认规则在 `T1`
退出，不得由 LLM 将“强逻辑”解释为例外。

## 7. 初始资金管理假设

以下比例仅用于模拟盘初始实验，不构成投资建议，后续必须依据回测和模拟结果
调整：

| 资金用途 | 初始测试范围 |
|---|---:|
| 现金缓冲 | 20%～30% |
| 波段趋势舱 | 50%～65% |
| 尾盘超短舱 | 10%～20% |

### 7.1 交易成本基线

第一阶段按东方财富证券账户的实际费率建立可配置成本模型：

| 费用 | 市场 | 收取方向 | 百分比 | 计算用小数 | 状态 |
|---|---|---|---:|---:|---|
| 印花税 | 沪深 A 股 | 卖出 | 0.05% | 0.0005 | 已确认 |
| 过户费 | 沪深 A 股 | 买卖双向 | 0.001% | 0.00001 | 已确认 |
| 佣金 | 沪市 | 买卖双向 | 0.00541% | 0.0000541 | 已确认 |
| 佣金 | 深市 | 买卖双向 | 0.00641% | 0.0000641 | 已确认 |
| 单笔最低佣金 | 沪深 A 股 | 买卖双向 | 5 元/笔 | 5.00 元 | 已确认 |

成本引擎必须：

- 按每笔成交分别计算费用，不得只按回测期总成交额估算。
- 区分沪市和深市佣金。
- 每笔佣金按 `max(成交金额 × 对应市场佣金率, 5 元)` 计算。
- 保存费率版本、生效日期和计算明细，确保历史回测可复现。
- 使用实际交割单定期校准；账户实际扣费口径与公开通用规则不一致时，
 以交割单为模拟账户校准依据，并保留差异记录。
- 在策略收益、止盈阈值和适应度计算中使用扣除佣金、税费和滑点后的净收益。

系统必须支持配置：

- 单票最大仓位。
- 单策略最大资金占用。
- 单行业最大风险暴露。
- 最大同时持仓数量。
- 单日最大新增仓位。
- 单日和单周最大亏损。
- 账户最大回撤。
- 连续亏损后的自动降仓。
- 行情异常和系统故障时的交易熔断。

## 8. 交易领域模型

系统必须明确区分以下对象：

| 对象 | 含义 |
|---|---|
| Quote / Bar | 带来源、时间和质量状态的行情数据 |
| Signal | 策略对标的的结构化观点 |
| TradePlan | 入场、仓位、止损、止盈和失效条件 |
| OrderIntent | 等待风控校验的订单意图 |
| ValidatedOrder | 已通过全部确定性风控的订单 |
| Fill | 实际或模拟成交结果 |
| Position | 成交后形成的持仓 |
| Portfolio | 现金、持仓、风险和权益状态 |

Signal 不能直接成为成交。所有订单必须经过统一的风险门。

## 9. A 股风险门

风险门至少校验：

- 股票代码、名称、交易所和证券状态完整。
- 行情价格为正且处于合理范围。
- 行情未过期，数据日期和交易日期一致。
- 排除 ST、退市整理、停牌和不可交易证券。
- 买入数量满足 A 股整手规则。
- 卖出满足 T+1 等适用交易规则。
- 委托价格满足涨跌幅限制。
- 现金和可用持仓充足。
- 不超过单票、单策略、单行业和账户风险上限。
- 相同策略、标的和交易日不能重复下单。
- 达到亏损或回撤熔断条件时停止新增风险。
- 数据源异常、系统异常或对账失败时默认拒绝交易。

## 10. 数据需求

### 10.1 市场数据

- A 股日线、周线和分钟线。
- 大盘和主要指数。
- 行业、概念及成分股。
- 实时或准实时行情。
- 成交量、换手率、涨跌停和停牌状态。

### 10.2 财务数据

- 利润表、资产负债表和现金流量表。
- 主要财务指标。
- 报告期和实际披露时间。
- 财务修订和数据来源。

回测只能使用当时已经公开的数据，不能使用后来修订或尚未披露的信息。

### 10.3 新闻和公告

- 交易所公告。
- 上市公司公告。
- 重要财经新闻。
- 行业政策和事件。

LLM 分析结果必须保留原始来源和时间，不能把无来源文本作为交易事实。

### 10.4 数据质量

每条数据至少记录：

- 数据源。
- 抓取时间。
- 市场时间。
- 复权方式。
- 数据版本。
- 校验状态。
- 缺失或异常原因。

### 10.5 东方财富客户端只读盘中采集

第一阶段允许将 Windows 上已由用户登录的东方财富客户端作为盘中行情辅助
数据源。该能力用于监控、核验和模拟交易，不是唯一行情来源，也不得用于实盘
下单。

采集器必须遵循以下边界：

- 优先使用 Windows UI Automation / `pywinauto` 读取行情和自选股控件；
 只有控件无法读取时才使用窗口截图与 OCR。
- 只允许连接明确列入白名单的行情、自选股、指数和板块窗口。
- 只允许读取最新价、涨跌幅、成交额、成交量、换手率、量比、当日高低点、
 盘口和分时状态等获准字段。
- 禁止打开或操作买入、卖出、委托、撤单、银证转账等交易功能。
- 禁止模拟键盘或鼠标执行任何证券交易操作。
- 禁止读取、截图、保存或上传账号、密码、验证码、资产、持仓和订单等
 账户敏感信息。
- 登录和身份验证必须由用户本人完成，系统不得保存或自动填写登录凭据。
- 窗口标题、进程身份、控件结构或客户端版本不符合已验证基线时，立即停止
 采集，不得通过坐标点击等方式绕过。
- 客户端锁定、退出登录、弹窗遮挡、采集失败或数据超过新鲜度阈值时，
 立即将数据源标记为不可用，并停止基于该数据产生新的盘中建议。
- 每条采集数据必须记录证券代码、字段名称、市场时间、采集时间、客户端版本、
 采集方式和质量状态；OCR 数据还必须记录识别置信度。
- 与其他数据源发生冲突时不得静默覆盖，必须记录差异并触发核验。

通用 Computer Use skill 不能直接取得该权限。若引入第三方 skill、MCP 或桌面
自动化组件，必须先审查源代码、许可证、网络通信、依赖和权限范围；金融账户
场景默认采用项目内自研的最小权限只读采集器。

## 11. 回测需求

回测必须建模：

- 佣金。
- 印花税。
- 过户费。
- 单笔最低佣金。
- 滑点。
- 涨跌停。
- 停牌。
- 无法成交和部分成交。
- A 股 T+1。
- 最小交易单位。
- 交易容量和流动性约束。

回测必须防止：

- 未来函数。
- 同一根 K 线产生信号并以不可获得的价格成交。
- 幸存者偏差。
- 使用当前股票池回测历史时期。
- 使用尚未披露的财务数据。
- 调参数据和最终测试数据混用。

标准报告至少包含：

- 累计收益和年化收益。
- 最大回撤。
- Sharpe 或其他风险调整指标。
- 胜率和盈亏比。
- 交易次数和样本量。
- 换手率。
- 手续费和滑点占比。
- 按年份、市场状态和策略资金舱拆分的表现。
- 样本外结果和置信区间。

## 12. LLM 需求

### 12.1 允许职责

- 财务报告和公告摘要。
- 新闻与事件结构化。
- 市场和行业状态解释。
- 个股风险梳理。
- 交易结果复盘。
- 提出可验证的新因子、参数或规则假设。
- 向用户解释策略推荐及失效条件。

### 12.2 禁止职责

- 绕过风险门。
- 自主决定真实下单金额。
- 直接修改活跃生产参数。
- 自动将策略晋升到实盘。
- 将无来源信息作为事实。
- 对收益作保证。

### 12.3 调用记录

每次重要 LLM 调用保存：

- 模型和服务商。
- Prompt 模板及版本。
- 输入数据摘要和引用来源。
- 原始输出。
- Schema 校验结果。
- 降级或失败原因。
- Token 和费用。
- 调用时间。

## 13. 遗传算法和自动进化

### 13.1 职责

GA 只在预先声明的参数范围内搜索，不允许生成任意代码或直接修改生产策略。

### 13.2 实验记录

每次实验必须记录：

```text
experiment_id
parent_experiment_id
created_at
strategy_name
strategy_version
git_commit
dataset_version
universe_version
train_period
validation_period
test_period
random_seed
parameters
parameter_bounds
llm_hypothesis
population_size
generation_count
fitness_definition
backtest_metrics
cost_model
failure_reason
promotion_decision
approval_record
```

### 13.3 实验谱系

每个实验都必须能追踪其父实验、参数变化、数据变化、结果变化和晋升理由。
任何活跃策略必须能反查到完整实验链。

### 13.4 适应度要求

适应度不能只优化收益率，至少综合考虑：

- 样本外收益。
- 最大回撤。
- 风险调整收益。
- 胜率和盈亏比。
- 交易次数。
- 换手和交易成本。
- 跨年份稳定性。
- 参数敏感性。
- 策略复杂度和过拟合风险。

任何 `NaN`、无穷值、样本不足或数据质量失败都必须使实验失败，不能被当作
零值或正常完成。

## 14. 策略晋升制度

| 等级 | 名称 | 要求 |
|---|---|---|
| Level 0 | 研究候选 | 在训练数据上验证基本逻辑 |
| Level 1 | 样本外候选 | 通过滚动验证和未参与调参的数据 |
| Level 2 | 影子模拟 | 使用真实市场数据生成决策但不记为成交 |
| Level 3 | 正式模拟盘 | 使用完整模拟账户、成本和风险规则 |
| Level 4 | 小资金实盘候选 | 完成合规、券商、技术和人工审批 |

策略晋升依据是证据门槛，不是进化次数。即使已进化十几次，如果样本外结果、
回撤、模拟偏差或系统稳定性不达标，也不能进入实盘。

## 15. Dashboard 和告警

Dashboard 至少展示：

- 账户权益、现金和回撤。
- 两个策略资金舱的独立绩效。
- 当前持仓和风险暴露。
- 今日信号、交易计划和失效条件。
- 数据新鲜度和数据源状态。
- 定时任务和系统健康状态。
- 当前活跃策略版本和实验来源。
- 最近实验、晋升和回滚记录。
- LLM 调用状态和费用。

告警至少覆盖：

- 止损、止盈和移动止损。
- 行情或财务数据过期。
- 持仓和订单对账失败。
- 重复订单。
- 账户回撤和连续亏损。
- 策略异常、系统故障和外部服务失败。
- 实验产生非法指标。

## 16. 非功能要求

### 16.1 安全

- 密钥不能进入 Git。
- 数据库和账户信息不能出现在日志中。
- 默认模式必须为 `paper`。
- 系统故障时默认拒绝交易。
- 必须有人工停止和全局熔断能力。

### 16.2 可重复性

- 锁定 Python 和依赖版本。
- 固定随机种子。
- 数据集、股票池和配置有版本号。
- 同一提交、数据和配置可生成相同结果。

### 16.3 可测试性

- 单元测试不依赖网络或真实 API Key。
- 每个外部数据源提供离线 Fake。
- 风控、费用和交易规则采用确定性测试。
- CI 至少执行编译、格式、静态检查和测试。

### 16.4 可追溯性

- 信号、计划、订单、风控、成交和持仓形成完整链路。
- 所有策略参数修改都有实验来源。
- 所有晋升、降级和回滚都有原因和审批记录。
- 关键记录采用追加写入，不能静默覆盖历史。

## 17. 实施阶段

### Phase 0：工程骨架

- 建立新的 `src/quantagent` 包。

## 18. 阶段验收标准

### 工程基线

- 干净环境可以按文档完成安装。
- 无密钥、无网络时全部单元测试通过。
- 编译、静态检查和测试在 CI 中通过。

### 风险核心

- 异常价格、过期数据、退市股和重复信号无法形成订单。
- T+1、整手、现金和仓位限制均有测试。
- 系统异常时默认拒绝交易。

### 回测

- 固定数据、代码、配置和随机种子产生确定性结果。
- 能检测未来函数和非法同周期成交。
- 报告包含成本、回撤、样本量和样本外表现。

### 策略

- 波段和超短资金舱分别回测和核算。
- 每个策略有明确入场、退出和失效条件。
- 策略结果不依赖少数极端交易。

### 进化

- 每次实验可完整复现。
- 非法指标会使实验失败。
- 活跃策略能够追溯到完整实验谱系。
- 没有人工批准不能晋升至更高交易等级。

### 模拟运营

- 连续运行至少 20 个交易日。
- 没有重复订单、静默任务失败或无法对账的持仓。
- 回测、影子模拟和正式模拟之间的偏差有完整分析。

## 19. 实盘门槛

进入真实自动交易前必须单独完成：

- 券商接口和权限确认。
- 程序化交易报告义务确认。
- 技术系统测试和风险评估。
- 账户、订单和成交对账。
- 密钥和账户安全审计。
- 人工接管、快速撤单和暂停申报能力。
- 小资金、低仓位灰度验证。
- 明确的回滚和停止条件。

中国证监会《证券市场程序化交易管理规定（试行）》自 2024 年 10 月 8 日起
施行；沪深交易所已发布程序化交易管理实施细则。系统若未来自动生成或下达
真实交易指令，应在接入前与券商确认适用的报告、测试和风险管理要求。

- 证监会规定：
  <https://www.csrc.gov.cn/csrc/c101954/c7480579/content.shtml>
- 上海证券交易所实施细则：
  <https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml>
- 深圳证券交易所实施细则：
  <https://docs.static.szse.cn/www/lawrules/rule/trade/W020250403603802169453.pdf>

## 20. 架构决策

采用“新核心逐步替换遗留系统”的路线：

1. 当前 QuantAgent 版本作为需求原型和策略素材归档。
2. 新核心从 `src/quantagent` 开始构建。
3. 先完成领域模型、风险门、模拟交易和可信回测。
4. 旧策略必须经过测试和新回测验证后才能迁移。
5. LLM 和 GA 在确定性交易核心稳定后接入。
6. 新系统覆盖全部必要能力后，删除遗留运行实现。

该决策的目标不是快速复制旧功能，而是建立一个未来可以安全验证真实资金的
可信量化基础。
